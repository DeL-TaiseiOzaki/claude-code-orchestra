# GUIDE.md Template

Template contract for the `GUIDE.md` onboarding document. `write_guide.py`
assembles the file from this layout; the `{placeholder}` tokens name the data
Phase 2 turns into prose, and `write_guide.py` rejects any that survive.

**Section numbers are part of the section names.** Omitting an optional section
never renumbers the rest — section 5 is `5. Capabilities` whether or not section
4 is present — because `validate_doc.py --contract guide` requires sections
`1. What is this project?`, `3. Recent Work`, `5. Capabilities`, and
`7. How to Resume Work` by their numbered names.

Sections 2, 4, 6 and 8 are OPTIONAL: omit one entirely when its source data is
absent. Sections 1, 3, 5 and 7 are always present.

## Section ids for `write_guide.py --input`

| Id | Heading | Necessity | Collector fields it draws on |
|----|---------|-----------|------------------------------|
| `what_is_this_project` | `1. What is this project?` | required | `identity`, `env.manifests`, `rules` |
| `current_state` | `2. Current State` | optional | `git.current_branch`, `git.status`, `git.stash`, `identity.state` |
| `recent_work` | `3. Recent Work (last 30 days)` | required | `git.log`, `git.recent_stat` |
| `architecture` | `4. Architecture & Key Decisions` | optional | `docs.design.key_decisions`, `docs.research`, `docs.libraries` |
| `capabilities` | `5. Capabilities` | required | `skills.items`, `agents.items` |
| `project_rules` | `6. Project Rules` | optional | `rules.items` |
| `resume_work` | `7. How to Resume Work` | required | `env.commands`, `env.scripts`, `skills.items` |
| `recent_sessions` | `8. Recent Sessions` | optional | `checkpoints.items`, `agent_teams`, `cli_tools.items` |

---

```markdown
# Project Guide

_Generated by `/catchup` on {YYYY-MM-DD}_

## 1. What is this project?

- **Purpose**: {one sentence from README/.agents/STATE.md identity}
- **Tech stack**: {language, package manager, key libraries — env.manifests}
- **Conventions**: {language for code / communication, lint / test tools}

## 2. Current State

- **Active branch**: {git.current_branch}
- **Current focus**: {identity.state.current_project / current_feature /
  current_bug_fix, if present}
- **Work in progress**: {git.status; omit section if none}
- **Stashed experiments**: {git.stash; omit if none}

## 3. Recent Work (last 30 days)

{3–7 thematic bullets grouping recent commits, with commit counts}

## 4. Architecture & Key Decisions

{Top 5 rows of docs.design.key_decisions with rationale}

### Active research threads
{docs.research items with 1-line summaries}

### Library constraints
{docs.libraries items with 1-line summaries}

## 5. Capabilities

### Slash commands
{Table: command — purpose, from skills.items name / short_description}

### Subagents
{Table: name — specialization, from agents.items}

## 6. Project Rules

{One-line summary per rules.items entry}

## 7. How to Resume Work

- **Environment setup**: {env.commands entries, with their source file}
- **Common commands**: {lint / test / run / build from env.commands, env.scripts}
- **Suggested next skills**: {derive from root `AGENTS.md` section
  "Routing Policy" and skills.items (e.g. `/feature`, `/spike`, `/troubleshoot`)}

## 8. Recent Sessions

### Checkpoints
{checkpoints.items — latest 5 checkpoint summaries}

### Agent Teams sessions
{agent_teams.sessions grouped by name, with teammates + task counts}

### Frequent CLI consultations
{cli_tools.items topics, grouped by tool}

---

_Sources: git log, .agents/STATE.md, .agents/rules/, .agents/skills/,
.agents/docs/, .agents/checkpoints/, .agents/logs/._
```

Do not leave placeholder text: `write_guide.py` exits 2 on any residual
`{token}` outside a fenced code block, so an unfillable section must be omitted
rather than shipped half-written. The title, the date line, and the `_Sources:_`
footer are emitted by `write_guide.py` and must not be supplied in `--input`.
