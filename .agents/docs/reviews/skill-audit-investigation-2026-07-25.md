## Keep as prose

These are judgment steps. Scripting them would make the skill rigid and wrong in
new situations — a proposal to automate any of them should be rejected.

- **Team design and pattern choice** — `team-execute/SKILL.md:86-120`. Which decomposition (module / layer / feature) fits *this* plan is judgment. Only the *consequence* — do the resulting ownership sets overlap — is mechanical, which is precisely the line `check_ownership.py` draws: it validates a map it never authors.
- **Model routing Sonnet vs Opus** — `team-execute/SKILL.md:122-130`, `:350-353`. The skill explicitly warns against routing by file count (`:127`), i.e. against the only rule a script could apply. Any automated router here would reproduce the failure mode the prose forbids.
- **Intervention triggers and escalation** — `team-execute/SKILL.md:232-240`. "Not making progress for a long time", "unexpected technical issue" are contextual reads, not thresholds.
- **Finding prioritization** — `team-execute/SKILL.md:516-521`, and severity assignment inside each reviewer prompt. Severity depends on exploitability and blast radius in context; a rubric table is the right level of formalisation.
- **All Codex prompt *content*** — `troubleshoot/SKILL.md:120-135, 204-281, 341-388`; `spike/SKILL.md:107-128, 237-319`. The Automation Boundary puts "Invoking external processes" in a script and "Composing the prompt content" in markdown (`_shared/README.md:16`); these skills already sit on the correct side of that line. Templating these prompts would strip the case-specific context that makes the consultation worth its cost.
- **The verdicts themselves** — GO / NO-GO / INCONCLUSIVE (`spike/SKILL.md:398-406`), CONFIRMED / ELIMINATED (`troubleshoot/SKILL.md:236`), root-cause identification, fix-approach trade-offs. Reading a verdict token *out of* a validated report is mechanical and fine; *computing* the verdict is the reasoning the skill exists to produce. Do not build a "decide GO" script.
- **Investigation mode, time budget, and short-circuit decisions** — `spike/SKILL.md:53-57, 93-101, 496, 501`. Budget discipline and "stop early, the answer is already clear" are the operator's call.
- **Bidirectional teammate communication** — `troubleshoot/SKILL.md:421-435`, `spike/SKILL.md:349-364`. The worked examples are illustrations of a discovery loop, not a protocol to encode.
- **The user-facing presentations** — `troubleshoot/SKILL.md:556-558`, `spike/SKILL.md:424-476`, `team-execute/SKILL.md:525-556`. Section *presence* can be validated cheaply (`validate_doc.py`); the prose inside them is the deliverable.
