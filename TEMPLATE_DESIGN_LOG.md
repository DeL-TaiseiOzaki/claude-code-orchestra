# Template Design Log (maintainer-facing)

> Append-only design log of the **Claude Code Orchestra template itself**.
> This file is NOT distributed: `scripts/install.sh` and `scripts/update.sh`
> never copy it into downstream projects. Downstream projects receive the
> blank placeholder `.agents/docs/DESIGN.md` and keep their own log there.
>
> **Policy:** every distributed workspace file (`.agents/docs/DESIGN.md`,
> `PROGRESS.md`, `research/`, `.agents/STATE.md`; `CLAUDE.md` is only a symlink) stays a placeholder in
> this repository. Decisions about the template's own architecture are
> recorded HERE, not in `.agents/docs/DESIGN.md`.

## Key Decisions

| Decision | Rationale | Alternatives Considered | Date |
|----------|-----------|------------------------|------|
| 3-tier agent hierarchy (default/sol/fable) redefined in repo terms | Maps vault's Sonnet/Sol/Fable onto orchestrator-direct + subagents / Codex / rare advisor without renaming existing machinery | Import vault terminology as-is (mismatch with Opus orchestrator design) | 2026-07-10 |
| Sol = gpt-5.6-sol at xhigh effort, bumped only at central points (settings.json env.CODEX_MODEL, .codex/config.toml) + fallback sweep | Single-point model management preserved; template self-consistency (SAFE_DIRS files are overwritten wholesale on update) | Per-file hardcoding; leaving stale prior-model fallbacks | 2026-07-10 |
| Keep approval_policy="never"; safety via completion-verification guardrails | Non-interactive hooks/Agent-Teams flows must not block; writes already require caller's explicit --sandbox workspace-write | Strict read-only default with approval escalation (blocks autonomous template flows) | 2026-07-10 |
| .agents/ = canonical spec for CLI subagents; .claude/ = main-agent spec; .codex/ = adapter | .codex-centric layout hindered adding other CLI subagents (Antigravity, Grok); user decision | Full centralization incl. .claude (drift risk without a generator); no neutral layer | 2026-07-10 |
| Tier-1 model norm: implementation subagents on Sonnet, research/large analysis on Opus 1M | Cost/perf split per task type; user decision | All-Opus (costly); all-Sonnet (loses 1M-ctx analysis) | 2026-07-10 |
| Fable = rare escalation advisor, differentiated from team-execute Phase 2 reviewers and /codex:adversarial-review | Scarcity keeps signal high; read-only + reviews/ output enforces "never implements" | Fable as routine reviewer (duplicates ship-gate reviews) | 2026-07-10 |
| _shared/ is a bundled runtime, not a skill: skills may depend on _shared/, never on each other | Preserves skill independence while deduplicating deterministic helpers; update.sh syncs skills dir atomically | Per-skill script duplication; cross-skill imports | 2026-07-10 |
| Document writers (Zone C append, DESIGN.md update) are scripts with typed-JSON input, dry-run default, --apply, atomic replace, stable-ID idempotency | Mis-writes to CLAUDE.md/DESIGN.md are the top risk of mechanized writes; structure validation + no-op/conflict semantics contain it | LLM edits documents directly from prose templates (re-interpretation risk) | 2026-07-10 |
| Embedded SKILL.md output templates moved to per-skill references/ as content contracts, not scaffold scripts | Templates are contracts, not computation; avoids generator API/test/empty-file debt (Codex recommendation, user-approved) | Scaffolder scripts pre-filling deterministic fields; keep templates inline | 2026-07-10 |
| codex exec invocations always append < /dev/null (and prefer timeout) | codex exec waits for stdin EOF and hangs indefinitely when stdin is left open — observed 27-minute hang in background shell | Leave stdin handling to callers (repeated hangs) | 2026-07-10 |
| Existing-project installation uses a conflict-aware installer with opt-in replacement backups | A template must not silently overwrite project-owned Claude/Codex configuration; default abort, Zone C preservation, settings merge candidates, and symlink escape checks make first-time installation reviewable | README cp -r one-liner; unconditional overwrite; updater-only bootstrap | 2026-07-16 |
| Store downstream Orchestra version state in .claude/orchestra-version and never update the downstream root VERSION | Root VERSION commonly belongs to the application receiving the template, so namespacing prevents template updates from corrupting the application's release version | Continue treating root VERSION as template-owned; omit installed-version tracking | 2026-07-16 |
| /init updates DESIGN.md and CLAUDE.md Zone B but never modifies root AGENTS.md | Root AGENTS.md is a template-owned discovery pointer to the canonical .agents contract and is fully replaced by template updates; project identity already has durable homes in DESIGN.md and CLAUDE.md Zone B | Store project identity in root AGENTS.md; make AGENTS.md a hybrid merged file | 2026-07-16 |
| Split the former single Claude execution agent into general-purpose-sonnet (default implementation) and general-purpose-opus (research, analysis, difficult implementation, and Codex delegation) | Task-based routing preserves Sonnet cost and speed for well-scoped work while allowing Opus for ambiguity, cross-system invariants, high-risk domains, or failed attempts; file count alone is not a capability signal | Single Opus agent for all tasks; single Sonnet agent for all tasks; route only by file count | 2026-07-16 |
| Set `sandbox_mode = "workspace-write"` in `.codex/config.toml` as the default (network access stays disabled) | User wants Codex to have edit permission by default instead of relying on every caller to remember `--sandbox workspace-write`; forgotten flags previously degraded silently to read-only; planning/review callers still pass explicit `--sandbox read-only`; Sol Guardrails completion verification (`.agents/AGENTS.md` section 8) remains mandatory regardless of sandbox mode | Keep read-only-by-default and require every caller to opt into workspace-write (status quo; error-prone) | 2026-07-18 |
| update.sh syncs each SAFE_DIR via per-directory stage-and-swap (rsync into `<dir>.orchestra-staging.$$`, rename swap through `<dir>.orchestra-old.$$`, EXIT/INT/TERM trap rollback) | Direct `rsync --delete` onto live directories left them half-updated on interruption; staging on the same filesystem makes the swap two atomic renames, the trap restores the original on mid-swap failure, and an interrupted run stays re-runnable; verified by a `mv`-shim failure-injection test | Keep direct rsync (status quo); all-dirs-staged-then-swap-all transaction (more debris states, no per-directory safety gain) | 2026-07-18 |
| install.sh verifies and repairs the `.codex/skills/design-tracker` relative symlink after copying template dirs | `cp -a` preserves symlinks, but tarball extraction or dereferencing copy paths can materialize or dangle it, silently forking the shared skill; post-copy verify + recreate keeps the Codex/Claude skill trees converged (update.sh's SAFE_DIRS full replace already self-heals on update) | Trust the copy method unconditionally; replace the symlink with a duplicated skill directory | 2026-07-18 |
| PostToolUse:Bash hooks consolidated behind a single `post-bash-check.py` dispatcher (in-process checks, targeted-hint dedup) | Three independent hooks spawned three python3 processes per Bash call with triple stdin parsing and a 25s cumulative timeout budget, and could emit redundant generic+targeted hints for the same failure; the dispatcher parses once, runs checks in-process via each script's pure function, and suppresses the generic error hint when the test-analysis hint fires; standalone `main()` entry points remain for direct invocation and the TaskCompleted wiring | Keep three independent hook entries (status quo); merge the three scripts into one file (loses standalone compat and the TaskCompleted separation) | 2026-07-18 |
| Template's own design log moved from `.claude/docs/DESIGN.md` to root `TEMPLATE_DESIGN_LOG.md` (not distributed) | `.claude/docs/DESIGN.md` is a PROJECT_FILES_IF_MISSING seed copied into downstream projects, so template-own decision rows polluted every downstream requirements doc; distributed workspace files must stay placeholders | Keep logging template decisions in DESIGN.md (pollutes downstream seeds); delete the log entirely (loses curated rationale) | 2026-07-18 |
| Antigravity CLI (`agy`) adoption staged: no adapter, no wiring, skeletons stay inactive until upstream closes the write-confinement gap | 2026-07 spike: `agy` passes 5/6 Tier-2 contract checks (headless `-p` exec without stdin hang, exit codes, `--model` pinning, `AGENTS.md`/`GEMINI.md` discovery, SKILL.md context loading) but headless mode auto-approves ALL tool calls including `write_file` (google-antigravity/antigravity-cli#45, unresolved, no maintainer response) and auth is OAuth-only (#78) — caller-side read-only override is impossible, violating the sol-tier planning/review pattern; re-spike ~2026-08/09 (v1.1.x changelog hints headless may honor settings.json permission policies) | Adopt now scoped to write-capable tasks only (OAuth blocks headless/CI use; contract exception complicates tiers.md); full NO-GO (5/6 capabilities already pass) | 2026-07-18 |
| Set `sandbox_mode = "danger-full-access"` in `.codex/config.toml` as the default, superseding the 2026-07-18 workspace-write decision | User explicitly requested Codex have every permission whenever it works in this environment, confirmed as an always-on default (not a per-task opt-in) after being shown the tradeoff; `approval_policy` was already `"never"`, so this removes the last remaining guardrail (sandbox confinement) — Codex now gets unrestricted filesystem and network access with zero confirmation prompts; Sol Guardrails completion verification (`.agents/AGENTS.md` section "Guardrails (Completion Verification)") remains mandatory regardless of sandbox mode; planning/review callers should still pass an explicit `--sandbox read-only` | Opt-in per-task via `codex exec --dangerously-bypass-approvals-and-sandbox` (keeps the workspace-write + network-disabled default; user declined in favor of an always-on default) | 2026-07-21 |
| Promote `.agents/ORCHESTRATION.md` to the shared, tool-neutral human-readable SSOT while keeping product-native runtimes and machine-readable settings in `.claude/` and `.codex/` | Mission, topology, routing, execution patterns, document ownership, quality gates, and language policy must be consistent for Claude Code, Codex, and future agents; a thin root bootstrap plus native adapters preserve standard discovery and the installer/updater's existing 3-zone and full-directory sync behavior | Keep `CLAUDE.md` as the main contract (CLI agents miss shared policy); centralize native JSON/TOML through a generator in this change (unnecessary migration and compatibility risk) | 2026-07-21 |
| Centralize shared rules, skills, agent definitions, and hooks under `.agents/`; make root `AGENTS.md` the hybrid 3-zone bootstrap/state file and `CLAUDE.md` a relative symlink to it | Policy-only centralization left the actual runtime knowledge owned by `.claude/`, so agents could still drift. Canonical `.agents/{rules,skills,agents,hooks}` content plus repaired native discovery symlinks gives every runtime one physical source while preserving Claude/Codex standard paths. The updater migrates existing CLAUDE.md Zone B/C state into AGENTS.md. | Keep real content under `.claude/` (rejected by user as incomplete centralization); remove 3-zone state entirely (would discard existing project identity and working-state compatibility) | 2026-07-21 |
| Supersede the hybrid-root design: keep root `AGENTS.md` to essential always-loaded instructions, symlink `CLAUDE.md` to it, and move mutable state/docs/logs/checkpoints plus all shared runtime content under `.agents/` | The root contract is paid for on every CLI-agent invocation, while `.claude/` ownership still fragmented the SSOT. `.agents/STATE.md` preserves project identity and working state without bloating the bootstrap; granular updater sync preserves project-owned context and legacy marker content is migration input only. | Hybrid 3-zone root AGENTS.md (too large and mutable); keep project docs/state under `.claude/` (incomplete centralization) | 2026-07-21 |
| Default the main agent to Claude Code and add `.agents/change_main.md` as an on-demand, tool-neutral change runbook | Claude remains the current orchestrator, but the architecture must permit Codex, Antigravity, or a future runtime to own user interaction without pre-creating product-specific adapters. Recording the active choice in project-owned `.agents/STATE.md` survives template updates. | Permanently hard-code Claude as main; preinstall adapters for every possible runtime | 2026-07-21 |
| Supersede the 9-line bootstrap: root `AGENTS.md` is the concise but complete shared Orchestra contract, including mission, non-goals, topology, routing, every bundled agent/skill, execution patterns, ownership, quality, language, and native boundaries; remove the duplicate orchestration rule | Every CLI agent loads root AGENTS.md, so it must explain what the Orchestra is and when each capability applies without requiring discovery of an index-only bootstrap. Full agent prompts and skill procedures remain canonical under `.agents/`, while AGENTS.md carries their decision-relevant catalog and the original Claude Code Orchestra operating model. | Keep the 9-line pointer-only bootstrap (too little operational context); duplicate the same orchestration contract in both AGENTS.md and `.agents/rules/orchestration.md` (drift) | 2026-07-21 |
| Keep `.claude/` and `.codex/` to product-native settings only; remove their shared-directory symlinks and make native settings reference canonical `.agents/` paths directly | The user requires a visible, enforceable ownership boundary: all human-readable rules, skills, agents, hooks, docs, logs, and checkpoints live only under `.agents/`. Root `AGENTS.md` catalogs every capability, `CLAUDE.md` links to it, Claude hooks execute from `.agents/hooks/`, and Codex skill configuration points to `.agents/skills/`. The updater migrates real legacy docs/logs/checkpoints with collision backups and rewrites the known legacy Claude hook prefix before deleting old native paths. | Retain native discovery symlinks (still makes native directories appear to own shared functionality); duplicate shared content (creates drift). This may forgo product UI auto-discovery that requires native directories, so capabilities are instead loaded through the always-read contract and direct native configuration where supported. | 2026-07-21 |
| Skill steps with exactly one correct output are bundled scripts; judgment steps stay in `SKILL.md`. Scripts share one contract: single JSON object on stdout, `--project-root`, exit vocabulary 0/1/2/3, errors never swallowed, stdlib only | Prose descriptions of mechanical steps drift silently — phases re-derived `{feature}`/`{topic}` slugs by hand so cross-phase artifacts stopped lining up, required document sections were omitted without detection, and `codex exec ... 2>/dev/null` made a crashed CLI indistinguishable from an empty answer. Scripting judgment steps instead would make skills rigid, so the split is the deliverable, not the scripting | Script whole skills (loses adaptability, the reason skills are markdown); leave everything in prose (status quo, silently inconsistent); per-skill one-off helpers without a shared contract (each with its own exit codes and output shape) | 2026-07-21 |
| One `codex_consult.py` wrapper replaces every hand-written `codex exec` invocation across skills, agents, rules, playbook, and hook hints | Prompt as a single argv element removes the nested-quoting breakage in the skills that embed Codex prompts inside teammate prompts; `stdin=DEVNULL` is the enforced form of the `< /dev/null` hang workaround; stdout/stderr are captured to `.agents/logs/codex/` so failures stay diagnosable; a timeout and a PATH check turn two silent hangs into reported errors. `.agents/check.sh` extends the single-point model check to the wrapper's `DEFAULT_MODEL` so centralized model management still holds | Keep the inline idiom and document the pitfalls (they were already documented and still recurred); a shell wrapper (same quoting exposure it is meant to remove) | 2026-07-21 |
| `validate_doc.py` holds every document section contract in one registry; no per-document validator and no compatibility shim | A template has no legacy to preserve, so a work-log-only validator with a divergent exit code (3 instead of 2 for the same condition) would ship a wart on day one; one engine means adding a contract is a registry entry, not a new script | Keep a `validate_work_log.py` shim for continuity (two exit-code conventions for one condition); one validator script per document type (duplicated section-extraction logic) | 2026-07-21 |
| Every `validate_doc.py` contract is pinned to the reference template it mirrors by a test that validates the template itself; heading matching ignores depth and accepts a required name as a whole-token prefix | A contract that rejects a document produced by following its own template verbatim is worse than no contract — it teaches agents that check failures are noise. The templates legitimately nest sections at different depths (`### Error` under a `## Bug Report:` title) and carry values in headings (`## Verdict: {GO / NO-GO}`), so the matcher accommodates both rather than forcing templates to a validator-friendly shape. The pinning test makes contract/template drift a test failure instead of a runtime surprise | Rewrite the templates to match strict exact-`##` matching (churns human-facing contracts to suit the checker); keep contracts hand-maintained and hope they stay aligned | 2026-07-21 |
| `.agents/check.sh` gains a "Skill scripts and docs in sync" check: every script path named in shared markdown resolves, and every bundled script is named in some markdown | The failure this catches is drift between a skill's prose and the scripts it invokes — a renamed or deleted helper leaves a documented command that fails at runtime, and an undocumented helper is dead weight nobody calls. Both are invisible to the test suite because they live in markdown | Rely on the pytest contract tests alone (they assert on document content, not on script/doc reachability); no check (status quo) | 2026-07-21 |
| Restore native discovery symlinks `.claude/agents` → `../.agents/agents` and `.claude/skills` → `../.agents/skills`, created and healed by install.sh/update.sh and verified by `check.sh`; supersedes the 2026-07-21 "native settings only, no symlinks" boundary | The purity boundary made `.agents/` the SSOT but silently broke Claude Code auto-discovery: subagents and skills are discovered ONLY from `.claude/agents`/`.claude/skills`, and neither path is configurable to point elsewhere (confirmed against current docs — skill-folder symlinking is officially supported; agents work via the discovery filesystem walk). Symlinks keep `.agents/` the single physical source (zero duplication, no drift) while giving native discovery. `.codex/skills` needs no link (Codex resolves skills via `config.toml` `path=`); hooks stay `.agents/hooks/` script paths in `settings.json`. Cross-CLI subagent invocation is documented in `cli-execution.md` (`claude -p` / `codex exec` / `gemini -p`). User decision after being shown the tradeoff | Sync-copy native dirs from `.agents/` (real files, Windows-safe, but re-sync on every change and drift risk); keep the no-symlink boundary and forgo native auto-discovery (status quo — the reported problem); CLAUDE.md `@import` (covers instruction text only, not subagents/skills) | 2026-07-24 |
| Cross-CLI subagent calls go through a shared wrapper per callee — `cli_consult.py` for Claude Code and Gemini, `codex_consult.py` for Codex — and `cli-execution.md` states access read-only-by-default with one visible flag per callee (`--permission-mode plan` / `--sandbox read-only` / `--approval-mode default`) | The cross-CLI section handed callers a raw `codex exec "<prompt>" < /dev/null` idiom, contradicting the project rule (enforced by `test_shared_script_contract.py`) that Codex is reached only through its wrapper, and left `claude -p` / `gemini -p` with no hardened path at all — reintroducing the stdin-EOF hang, lost stderr, nested-quote breakage, and missing deadline for every peer CLI. One implementation per callee (Codex is refused by `cli_consult.py`) keeps Codex's sandbox/`--config` validation in one place instead of forking it. Claude's `--output-format json` envelope is unwrapped so `response_head` is the answer, its `session_id` enables `--resume` chaining, and `is_error: true` fails the call even on exit 0; Gemini's text output is captured verbatim because its JSON mode has known gaps (google-gemini/gemini-cli #9009, #9281) | One generic wrapper that also drives Codex (either duplicates the sandbox/config validation or forces fragile flag translation through `codex_consult.py`); keep documenting raw headless commands and rely on callers to remember four pitfalls (already tried for Codex, recurred) | 2026-07-25 |
| `log-cli-tools.py` recognizes wrapper invocations and logs from the wrapper's JSON result; the bare-`codex exec` path is tokenized from the end instead of regex-matching the first quoted string | `.agents/logs/cli-tools.jsonl` is advertised in `cli-execution.md` as the cross-agent record of what was delegated, but the extractor required an inline quoted prompt followed by `2>/dev/null` — the exact idiom the project banned in 2026-07-21. Every mandated call passes `--prompt-file`, so the log was silently always empty, and the only test covering it exercised the banned form. Entries now carry `via` (wrapper vs direct) and `response_file`, and success comes from the wrapper's own `ok` field rather than "exit 0 and non-empty stdout" | Delete the log and the references to it (loses the cross-runtime handoff record); log every Bash command containing "codex" including `--help` (noise) | 2026-07-25 |
| `update.sh` copies SAFE_DIRS into staging with `cp -a` instead of `rsync -a --delete` | The staging directory is created empty immediately before the copy, so `--delete` had nothing to delete and rsync's only remaining job was an attribute-preserving tree copy. rsync is absent from minimal images (containers, CI runners), where the updater died with exit 127 partway through the run — five `test_install_script.py` tests failed for that reason alone. coreutils ships everywhere python3 does | Keep rsync and add a preflight dependency check (still blocks the update on a missing tool it does not need); dual rsync/cp code paths (two behaviors to keep in sync) | 2026-07-25 |
